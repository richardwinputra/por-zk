# Policy-Bound Proof of Reserve (PoR-ZK)

Reproducibility artifact for the ICT Express manuscript *"Stablecoins Proof of Reserve via Zero-Knowledge Proofs"*. This repository contains the Noir circuits, TypeScript orchestration code, scenario data, and result artifacts referenced from §5 of the paper.

## Contents

| Path | What's inside |
|---|---|
| `circuit/` | Policy-bound circuit (Schnorr-attested, policy-hash-checked solvency over 10 slots). Source: `circuit/src/main.nr`. |
| `circuit_baseline/` | Solvency-only baseline used for the overhead comparison (Table 4). |
| `ts/src/` | TypeScript drivers: witness builder, Schnorr signer, Pedersen hasher, scenario runners. |
| `data/case_study/` | USDC March-2023 case-study data (attested values, illustrative per-bank split, and the three policy JSONs for 9a/9b/9c). |
| `data/results/` | All numeric outputs that back the paper: bench CSVs, correctness CSV, case-study CSV, summary tables, `paper_values.md`, `figure1.{pdf,png}`, and the run manifest. |
| `analysis/` | Python scripts that turn the raw CSVs into the markdown tables and the figure. |

## Versions

- Noir / nargo: `1.0.0-beta.3`
- Barretenberg (`bb`) and `bb.js`: `0.82.2`
- `noir-lang/schnorr` crate: `v0.1.3`
- Node: `v23.5.0`; Python: `3.9.6`
- Reported machine: Apple M1 Pro, 8 cores, 16 GB. Full run manifest: `data/results/run_manifest.json`.

## Reproducing the results

```bash
# 1. Install the TS driver
cd ts && pnpm install      # or npm install
cd ..

# 2. Compile both circuits and capture meta (gates, opcodes, compile time)
nargo compile --package circuit
nargo compile --package circuit_baseline
bb write_vk -b circuit/target/circuit.json -o circuit/target/vk
bb write_vk -b circuit_baseline/target/circuit_baseline.json -o circuit_baseline/target/vk

# 3. Run the experiments
cd ts
pnpm run manifest
pnpm run correctness         # 22 functional scenarios -> correctness.csv
pnpm run paired              # paired governance-effect demo -> paired.csv
pnpm run case_study          # USDC 9a/9b/9c -> case_study.csv
pnpm run bench               # 5 configs x 30 reps, policy circuit -> bench.csv
pnpm run bench_baseline      # 5 configs x 30 reps, baseline circuit -> bench_baseline.csv
cd ..

# 4. Build tables and figure
python3 analysis/summarize.py
python3 analysis/overhead_measured.py
python3 analysis/plot_bench.py
python3 analysis/paper_export.py
python3 analysis/check_consistency.py
```

The benchmark runners use a deterministic shuffled schedule seeded from `bench_seed` in `data/results/run_manifest.json` (default 4242).

## Auditor key

`data/auditor_key.json` is a **deterministic test keypair** derived from the seed `0xabcd` (see `loadOrCreateAuditorKey` in `ts/src/schnorr.ts`). It is published as part of the artifact so that the bundled proofs can be re-verified bit-for-bit. It is not a production key and must not be reused outside this artifact.

## Notes on the dataset

- All 150 + 150 benchmark rows are retained, including a small number of warm-run outliers attributable to OS-scheduling interruption on the test machine; medians (the primary statistic in Tables 3 and 4) are unaffected. See the table-3 and table-4 captions for specifics.
- Proof size is invariant across all 150 policy-bound runs (`14212 B`) and across all 150 baseline runs (`14116 B`); the 96 B difference equals exactly three additional 32-byte field elements corresponding to the three extra public inputs `{h_p, auditor_pk_x, auditor_pk_y}` in the policy-bound circuit.
- Some files in `data/results/` (notably `correctness.csv` and `case_study.csv`) embed Noir compiler error messages that include the absolute path to `circuit/src/main.nr` from the machine the experiment was run on. These paths are diagnostic only; they do not affect any of the reported figures.
